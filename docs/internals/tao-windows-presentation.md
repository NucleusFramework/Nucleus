# Windows presentation: blt + DirectComposition mirror

**Windows presentation = blt + DirectComposition mirror** (`nucleus_tao_gl.c`, `nucleus_tao_gl_mirror.cpp`). ANGLE's HWND swapchain is blt-model: its present lands in the GDI redirection surface **clipped at the desktop's edge**, so a frame presented while the window is partly off-screen never reached DWM there (white/stale band when dragged into view, and in the taskbar thumbnail / Alt+Tab, drawn from the same copy; flutter/flutter#102390 is the same bug, open). But only the blt present lands in step with a window geometry change — no flip-model or DComp present can be tied to one (Chromium removed its attempt, CL 7994218; WinUI 3, Zed, Terminal live with the tremble; measured here: `ResizeSyncHeadfulCases`, 30/307 frames off the border with a flip chain, 0 with blt). So both, only where it matters: every frame is still blt-presented, and **while the window overhangs the desktop** (`windowOverhangs`: `EnumDisplayMonitors` coverage, cached per window rect; a window fully on-screen loses nothing to the blt clip and has no mirror allocated at all — the first frame swapped fully on-screen releases it) also `glBlitFramebuffer`-copied (rows flipped, GL bindings restored) into an EGLImage over a D3D11 texture shown by a **non-topmost** DComp visual on the render child (`CreateTargetForHwnd(child, FALSE)`: above the window's own Present content, under child windows → NativeViews stay on top). The deco subclass's `WM_WINDOWPOSCHANGING` (real size change) calls `nucleus_tao_window_size_changing` to take the visual down *before* the geometry reaches DWM — the blt content under it is the same frame — (then `WaitForCommitCompletion` + `DwmFlush`: a processed commit is not yet a shown composition, and without the flush one frame in ~300 showed the old frame in the new bounds at the start of a drag), and a 200 ms WM_TIMER on the render child brings it back from the texture once the texture has the child's size — whether or not a frame came since (a restore to the same size, a window with nothing to redraw, bring none). Any mirror failure (no dcomp.dll / EGLImage extension, `CreateTargetForHwnd`, swapchain) latches `mirrorBroken` for that window — never retried per frame — and `nativeNeedsRepaintOnMove` puts the repaint-on-move back; the move frame sets `forcePresentOnce`, since a clean frame is otherwise skipped and nothing would reach DWM. Opaque windows only (`syncMirror`, whose native call answers whether the driver can mirror: a transparent window or an armed backdrop would get the translucent frame twice); those keep the repaint-on-move. Do **not** replace the blt present with a flip chain on the child HWND: tried, measured, reverted (trembling resize, white bands). E2E: `OffScreenPresentHeadfulCases` (DWM copy via `PrintWindow(PW_RENDERFULLCONTENT)`, screen via `CAPTUREBLT`, top band for orientation, per-pixel alpha), `ResizeSyncHeadfulCases` (content edge vs window edge, filmed row), `UnpaintedFlashHeadfulCases` (white on open / grow / border drag).
