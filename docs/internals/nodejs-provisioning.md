# Node.js provisioning

**Node.js is provisioned, not required**: every format except `TargetFormat.RawAppImage` is built by electron-builder, which the plugin installs with `npm ci --ignore-scripts` against an embedded lock file — so packaging needs a Node.js. It downloads one from `nodejs.org` (verified against the release's `SHASUMS256.txt`) into `<gradle-user-home>/nucleus/nodejs`, exactly like the GraalVM and packaging JDK toolchains, and the three share `ToolchainDownloads`. Configure with `nativeDistributions { nodejs { autoDownload / version / installDir } }`; `version` is a major line (`"22"`, the default), `"lts"`, or a pinned release, and a floating line is sticky once downloaded. Precedence: the `compose.electronBuilder.nodePath` Gradle property, then `NUCLEUS_NODE_HOME`, then the provisioned install, then `PATH` (also the fallback when the download fails). CI therefore runs **no** `actions/setup-node`, and does not cache `~/.gradle/nucleus/nodejs` either (nor the GraalVM toolchain): those per-ref entries pushed the repo past the 10 GB Actions cache limit and got the Gradle caches evicted. `release-desktop`'s `universal-macos` job runs electron-builder outside the plugin, so `build-macos-universal/provision-electron-builder.sh` mirrors it: same Node resolution rule, same install layout and marker, and `npm ci --ignore-scripts` against the plugin's embedded lock file — never `npx --yes`
