# ProGuard consumer rules

**ProGuard consumer rules**: standalone ProGuard never reads the rules libraries embed (Guardsquare/proguard#337; R8 and AGP do), so `AbstractProguardTask` extracts `META-INF/proguard/*` (direct files, any name — AGP's rule) from every input JAR, the app's own included, and `-include`s them after the default rules, before `configurationFiles` (`ConsumerProguardRules`). `META-INF/com.android.tools/` is never read: its `proguard` variants repeat the legacy files, its `r8*` variants carry R8-only syntax ProGuard rejects (`kotlinx-serialization-r8.pro`). Files are renamed by the plugin (no Zip Slip), deduplicated by content (shaded JARs repeat their dependencies' rules), and a file using any option outside the allowlist `ConsumerRuleGuard.ALLOWED_OPTIONS` (keep / `-if` / attributes / `-dontwarn` / `-dontnote` / `-assume*` / `-adapt*`, spelled in full) or the `@file` include is skipped with a warning — an allowlist because ProGuard accepts any prefix of an option (`-incl`, a bare `-` is `-include`) and has aliases (`-defaultpackage`), so a deny-list always missed one; files are tokenized like ProGuard's word reader (`{ *; }-dontobfuscate` is caught), and a quote outside a comment rejects the file outright — ProGuard ends a word at a quote and unquotes it (`'a.B'-dontshrink`, `'-printconfiguration'`), and no library rule file checked uses quotes; so does any character but printable ASCII and tab outside a comment (ProGuard reads UTF-8 and splits on `Character.isWhitespace`, U+001C–U+001F and Unicode separators included, so `a<U+001C>-dontshrink` is two words to it); a top-level `@` counts as an annotation only when a name is glued to it and a class specification follows, anything else (a bare `@ x.pro` included) is an include; and a top-level `{` is only accepted after a class-specification option (`-keep*`, `-if`, `-assume*`) — a file filter takes a bare `{` as a value (`-adaptresourcefilenames {`), which would hide a following `@file` from the brace count; and a `#` glued to a word is refused, since after a file filter option ProGuard reads file names, where `#` only starts a comment after whitespace (`-keepdirectories a#b -dontobfuscate`). A `META-INF/services` file that is no provider list (Groovy's `ExtensionModule` properties) is ignored without a warning. **Opt-in** (it keeps more than an existing configuration did): `proguard { consumerRules = true }`, `excludeConsumerRules("com.squareup.*:*", ":shared")` (drops the dependency's rule files only — its `META-INF/services` providers stay kept, or excluding a bad rule file would silently lose a JDBC driver; a Kotlin Multiplatform library also matches by its declared module, without the `-jvm` / `-desktop` it resolves to; a pattern matching no input JAR is warned about; coordinates from the runtime configuration's resolved artifacts; `fromFiles` apps have none, so only the switch applies). Without it, OkHttp/jsoup's `-dontwarn`s were missing and the release build failed outright. The same pass turns every `META-INF/services` file into keep rules (`ServiceProviderRules`, last `NNN-service-providers.pro`): providers keep their name and constructor — conditionally (`-if class <service>`) when the service ships in the app, always for a JDK service such as `java.sql.Driver`; names are validated as binary names so a service file cannot inject options; `javax.annotation.processing.Processor` is skipped. The default rules also keep enum `values()` / `valueOf()` (an `EnumMap` of a shrunk enum failed with `keyUniverse is null`). Measured on ~70 popular libraries (`C:\tmp\pg-eco` style bench: Ktor, Jackson, OkHttp, Logback, Picocli…), these took a release from 40 to 47 of 72 runtime checks (46 → 54 unoptimized), none regressed. Library rules are tuned for R8: ProGuard's optimizer still strips Gson's `@SerializedName` field annotations, which needs an app-side `-keep` of the model class
